# POST `/chat/turn` — Frontend Integration Guide

> RetailGPT Customer Support API
> Base URL: `https://<your-domain>` or `http://localhost:8000` locally

---

## Overview

The `/chat/turn` endpoint is the single endpoint your frontend calls on every customer interaction — whether the customer types a message, clicks an option button, or completes an upload.

The backend is **completely stateless**. It reads everything it needs from the request and returns the updated state in `next_context`. Your frontend is responsible for storing `next_context` and sending it back on every subsequent turn.

---

## Request

### `POST /chat/turn`

**Content-Type:** `application/json`

### Request Body

```json
{
  "session_id":   "sess_abc123",
  "customer_id":  "cust_xyz",
  "message":      "mera dal thanda tha",
  "message_type": "text",
  "option_id":    null,
  "context": {
    "current_flow":   null,
    "flow_step":      null,
    "category":       null,
    "order_id":       null,
    "turn_count":     0,
    "negative_turns": 0,
    "fallback_count": 0,
    "open_handovers": []
  },
  "transcript": [
    { "role": "customer", "content": "mera dal thanda tha" }
  ]
}
```

### Fields

| Field | Type | Required | Description |
|---|---|---|---|
| `session_id` | `string` | Yes | Unique session ID generated by the frontend |
| `customer_id` | `string` | No | Customer identifier — sent at the top level every turn |
| `message` | `string` | Yes | Customer message text (1–2000 chars) |
| `message_type` | `string` | No (default: `"text"`) | Type of message — see [Message Types](#message-types) |
| `option_id` | `string \| null` | No | ID of selected button — required when `message_type` is `"option_select"` or `"upload_complete"` |
| `context` | `ChatContext` | No (default: empty) | State object returned by previous turn's `next_context`. Send empty on the first turn. |
| `transcript` | `array` | No (default: `[]`) | Full conversation history — append before every send |

### `ChatContext` Object

> Returned in every response as `next_context`. Store it and send it back unchanged on the next request.

| Field | Type | Default | Description |
|---|---|---|---|
| `current_flow` | `string \| null` | `null` | Active flow ID (e.g. `"flow_order_status"`) |
| `flow_step` | `string \| null` | `null` | Active step ID within the flow graph |
| `category` | `string \| null` | `null` | Product category detected (`"fb"`, `"grocery"`, `"fashion"`, `"electronics"`) |
| `order_id` | `string \| null` | `null` | Order ID captured from NLU or order-select step |
| `turn_count` | `int` | `0` | Number of completed turns |
| `negative_turns` | `int` | `0` | Count of turns with negative sentiment (escalates at 2) |
| `fallback_count` | `int` | `0` | Count of unrecognised intents (escalates at 3) |
| `open_handovers` | `array` | `[]` | Active escalation tickets |

### Message Types

| `message_type` | When to use | `option_id` | NLU runs? |
|---|---|---|---|
| `"text"` | Customer typed a message | `null` | Yes — intent, category, sentiment extracted |
| `"option_select"` | Customer clicked an option button | Required — must match a button's `id` | No |
| `"upload_complete"` | Customer finished uploading files | Set to `"upload_complete"` | No |

## Response

```json
{
  "render_type":     "options",
  "message":         "I'm sorry to hear that! What type of order was it?",
  "options":         [
    { "id": "fb",      "label": "🍕 Food & Beverages (F&B)" },
    { "id": "grocery", "label": "🛒 Grocery" }
  ],
  "upload_config":   null,
  "terminal":        false,
  "escalate":        false,
  "escalate_reason": null,
  "ai_summary":      null,
  "ticket_raised":   false,
  "issue_type":      null,
  "next_context": {
    "current_flow":   "flow_items_detect",
    "flow_step":      "flow_items_detect",
    "category":       "fb",
    "order_id":       null,
    "turn_count":     1,
    "negative_turns": 0,
    "fallback_count": 0,
    "open_handovers": []
  },
  "nlu": {
    "intent":     "wrong_item",
    "category":   "fb",
    "confidence": 0.92,
    "sentiment":  "negative",
    "order_id":   null,
    "entities":   ["dal"],
    "source":     "llm"
  }
}
```

### Response Fields

| Field | Type | Description |
|---|---|---|
| `render_type` | `string` | How to render this response — see [Render Types](#render-types) |
| `message` | `string` | Bot message text to display |
| `options` | `array \| null` | Clickable buttons — present when `render_type` is `"options"` |
| `upload_config` | `object \| null` | Upload requirements — present when `render_type` is `"upload"` |
| `terminal` | `bool` | `true` means this is a final message; disable input and show restart prompt |
| `escalate` | `bool` | `true` means the conversation is being handed off to a human agent |
| `escalate_reason` | `string \| null` | Why the escalation happened — see [Escalation Reasons](#escalation-reasons) |
| `ai_summary` | `string \| null` | AI-generated conversation summary for the agent — only set when `escalate=true` |
| `ticket_raised` | `bool` | `true` means a support ticket was created on this turn |
| `issue_type` | `string \| null` | Category of the raised ticket — see [Issue Types](#issue-types) |
| `next_context` | `ChatContext \| null` | Updated state to send back next turn. `null` when `escalate=true` |
| `nlu` | `NLUOutput \| null` | NLU results — only set when `message_type` was `"text"` |

### `options` Array Item

```json
{ "id": "yes", "label": "Yes, I just placed it" }
```

| Field | Description |
|---|---|
| `id` | Send this as `option_id` in the next request when the user clicks this button |
| `label` | Display text for the button |

### `upload_config` Object

```json
{
  "required":    true,
  "min_photos":  3,
  "video":       true,
  "max_size_mb": 20
}
```

| Field | Type | Description |
|---|---|---|
| `required` | `bool` | Always `true` on upload steps |
| `min_photos` | `int` | Minimum number of photos the customer must attach |
| `video` | `bool` | `true` means at least one video is required alongside photos |
| `max_size_mb` | `int` | Maximum size per file in MB |

### `nlu` Object

| Field | Type | Description |
|---|---|---|
| `intent` | `string` | Detected intent (e.g. `"quality_issue"`, `"track_order"`, `"unknown"`) |
| `category` | `string` | Detected category (`"fb"`, `"grocery"`, `"fashion"`, `"electronics"`, `"unknown"`) |
| `confidence` | `float` | Confidence score `0.0–1.0` |
| `sentiment` | `string` | `"positive"`, `"neutral"`, or `"negative"` |
| `order_id` | `string \| null` | Order ID extracted from the message if present |
| `entities` | `array` | Named entities extracted (e.g. product names) |
| `source` | `string` | `"llm"` (Gemini) or `"keyword"` (fast keyword match) |

## Render Types

The `render_type` field tells your frontend exactly what UI to show.

### `"options"` — Show choice buttons

> Disable the text input and show option buttons. Wait for the user to click.

```json
{
  "render_type": "options",
  "message":     "What type of order is it?",
  "options": [
    { "id": "fb",      "label": "🍕 Food & Beverages (F&B)" },
    { "id": "grocery", "label": "🛒 Grocery" },
    { "id": "fashion", "label": "👗 Fashion & Apparel" }
  ]
}
```

**Frontend action:**
1. Display `message` as a bot bubble
2. Render each item in `options` as a clickable button
3. Disable the text input field
4. On button click → send `message_type: "option_select"` with `option_id` = clicked button's `id`
5. Disable all buttons immediately on click to prevent double-submission

**Edge case — empty options:**
If `options` is `null` or `[]`, show an info notice and re-enable the text input:
```
"No options available. Please type your message or start a new chat."
```

---

### `"upload"` — Show upload card

> Disable text input, show a media upload UI. After upload completes, send a follow-up request.

```json
{
  "render_type":   "upload",
  "message":       "Please upload 3 photos of the items received. Ticket #XXXX created.",
  "upload_config": { "required": true, "min_photos": 3, "video": false, "max_size_mb": 20 },
  "ticket_raised": true,
  "issue_type":    "incorrect_item"
}
```

**Frontend action:**
1. Display `message` as a bot bubble
2. Show an upload card with the requirements from `upload_config`
3. Optionally show a ticket badge if `ticket_raised=true`
4. Validate before allowing submit:
   - File count `≥ min_photos`
   - Each file size `≤ max_size_mb MB`
   - If `video=true`, at least one video file required
5. After upload completes, send:

```json
{
  "message":      "upload_complete",
  "message_type": "upload_complete",
  "option_id":    "upload_complete",
  "context":      { ...previous next_context... }
}
```

---

### `"handover"` — Escalation to human agent

> Terminal state. Disable all input. The conversation has been handed off.

```json
{
  "render_type":     "handover",
  "message":         "Let me connect you to a support agent who can help you with this.",
  "escalate":        true,
  "escalate_reason": "flow_endpoint",
  "ai_summary":      "Customer received incorrect items in F&B order #ORD-123. Photos uploaded. Refund requested.",
  "next_context":    null
}
```

**Frontend action:**
1. Display `message` as a bot bubble
2. Show a handover card with:
   - `escalate_reason` (debug/info label)
   - `ai_summary` — the full summary for the agent (display or log it)
3. Disable text input permanently
4. Update placeholder: `"Session ended — click New Chat to start over"`
5. `next_context` is `null` — no further turns are possible

---

### `"text"` — Informational message

> Show text, re-enable input unless `terminal=true`.

```json
{
  "render_type": "text",
  "message":     "Your order has been successfully cancelled. ✅",
  "terminal":    false
}
```

**Frontend action:**
- Display `message` as a bot bubble
- If `terminal=false` → re-enable text input
- If `terminal=true` → disable input, show restart prompt

---

### `"text_input"` — Free-text prompt

> Show a text field. The user types a free-form response.

```json
{
  "render_type": "text_input",
  "message":     "Please type any special delivery instructions for the delivery partner:"
}
```

**Frontend action:**
1. Display `message` as a bot bubble
2. Show (or keep enabled) the text input field
3. User types and sends normally with `message_type: "text"`

## The Stateless Pattern

The backend holds no session state. Every request must carry the full conversation state.

### Turn lifecycle

```
┌─────────────────────────────────────────────────────────────────┐
│ TURN N                                                          │
│                                                                 │
│ Frontend sends:                                                 │
│   session_id, customer_id, message, message_type, option_id     │
│   context  ← next_context from TURN N-1 (empty on first turn)  │
│   transcript ← all messages so far                             │
│                                                                 │
│ Backend returns:                                                │
│   render_type, message, options / upload_config                 │
│   next_context ← store this, send it back on TURN N+1          │
│   ticket_raised, issue_type, escalate, ai_summary, nlu          │
└─────────────────────────────────────────────────────────────────┘
```

### Transcript maintenance

```js
// Before sending each turn — append customer message
transcript.push({ role: 'customer', content: userMessage });

// After receiving response — append bot message
transcript.push({ role: 'bot', content: response.message });
```

### Context update

```js
// After receiving response
if (response.next_context) {
  context = response.next_context;
}
// When escalate=true, next_context is null — do not overwrite
```

## Complete Flow Examples

### Example 1 — Order Status (Happy Path)

```
Turn 1: User types "Where is my order?"
  → message_type: "text"
  → NLU: intent=track_order, category=unknown
  → Response: render_type="options"
              message="Which category is your order?"
              options=[{id:"fb",...}, {id:"grocery",...}]

Turn 2: User clicks "Food & Beverages (F&B)"
  → message_type: "option_select", option_id: "fb"
  → Backend: fetches orders API for customer_id + category=F&B
  → Response: render_type="options"
              message="Please select the order you'd like to check:"
              options=[{id:"ORD-101", label:"Paneer Pizza ×1 (Mar 10, 2026)"}]

Turn 3: User clicks the order
  → message_type: "option_select", option_id: "ORD-101"
  → context.order_id is now "ORD-101"
  → Response: render_type="options"
              message="Your yummy food is on the way! 🚀"
              options=[{id:"more",...}, {id:"done",...}]

Turn 4: User clicks "No, I'm good 👍"
  → Response: render_type="options"
              message="Thank you! Would you like to rate your experience?"
              options=[⭐⭐⭐⭐⭐, ⭐⭐⭐⭐, ...]
```

---

### Example 2 — Quality Issue (Upload + Escalation)

```
Turn 1: User types "food was cold and stale"
  → NLU: intent=quality_issue, category=fb, sentiment=negative
  → Response: render_type="options"
              message="Which category is your order?"

Turn 2: option_id="fb"
  → Backend: fetches orders API
  → Response: render_type="options"
              message="Please select the order with the quality issue:"
              options=[order items from API]

Turn 3: option_id="ORD-55"  (order selected)
  → Response: render_type="options"
              message="What type of quality issue did you experience?"
              options=[{id:"stale",...}, {id:"wrong_taste",...}, ...]

Turn 4: option_id="stale"
  → Response: render_type="options"
              message="Was the food stale or beyond use-by date?"
              options=[{id:"yes",...}, {id:"no",...}]

Turn 5: option_id="yes"
  → Response: render_type="upload"
              message="Please upload 3 photos 📷 and 1 video 🎥. Ticket #XXXX created."
              upload_config: { min_photos:3, video:true, max_size_mb:20 }
              ticket_raised: true
              issue_type: "quality_issue_fb"

Turn 6: upload done → option_id="upload_complete"
  → Response: render_type="options"
              message="Connecting you to an agent for verification..."
              options=[{id:"ok", label:"Okay, I'll wait"}]

Turn 7: option_id="ok"
  → Response: render_type="handover"
              escalate: true
              escalate_reason: "flow_endpoint"
              ai_summary: "Customer received stale food. Evidence uploaded. Refund review initiated."
              next_context: null
  → SESSION ENDS
```

---

### Example 3 — No Orders Found (Grocery Fallback)

```
Turn 1: option_id="grocery" (from items issue flow)
  → Backend: grocery not supported by orders API — skips API call
  → Moves to next step automatically
  → Response: render_type="options"
              message="We couldn't find any recent orders for your account.
                       Please select the issue:"
              options=[{id:"incorrect",...}, {id:"missing",...}]
```

> The `"We couldn't find any recent orders for your account."` prefix is prepended automatically.
> Render it as a normal bot message.

## Escalation Reasons

When `escalate=true`, the `escalate_reason` field explains why:

| `escalate_reason` | Trigger |
|---|---|
| `"customer_requested"` | User explicitly asked to speak to an agent |
| `"bot_fallback_limit_reached_3"` | 3 consecutive unrecognised intents |
| `"customer_frustrated_2_negative_turns"` | 2+ turns with negative sentiment |
| `"payment_query_mandatory_escalation"` | Any payment or billing query |
| `"electronics_mandatory_escalation"` | Electronics quality issue (always escalates) |
| `"repeat_complaint_open_ticket_{id}"` | Customer already has an open ticket for this order/issue |
| `"flow_endpoint"` | Reached a flow step whose transition is `ESCALATE` |

---

## Issue Types

When `ticket_raised=true`, the `issue_type` field identifies the category of support ticket:

| `issue_type` | Flow | Description |
|---|---|---|
| `"incorrect_item"` | F&B items issue | Wrong items delivered |
| `"missing_item"` | F&B items issue | Items missing from order |
| `"incorrect_or_missing_item"` | Grocery items issue | Incorrect or missing items |
| `"quality_issue_fb"` | F&B quality | Cold, stale, burnt, wrong taste, spillage |
| `"quality_issue_grocery"` | Grocery quality | Spoiled, expired, wrong brand, spillage, broken seal |
| `"quality_issue_fashion"` | Fashion quality | Size, fit, colour, fabric defect, damage |
| `"quality_issue_fashion_packing"` | Fashion packing | Packaging damaged on delivery |
| `"quality_issue_electronics"` | Electronics quality | Not working, damaged, colour, brand mismatch |
| `"quality_issue_electronics_packing"` | Electronics packing | Packaging damaged on delivery |

## Session Initialisation

Generate a new session ID on each fresh conversation and pass empty context:

```js
function newSession(customerId) {
  const sessionId = 'sess_' + Math.random().toString(36).slice(2, 10) + Date.now().toString(36);
  const context   = { turn_count: 0, negative_turns: 0, fallback_count: 0, open_handovers: [] };
  const transcript = [];
  return { sessionId, context, transcript, customerId };
}
```

## Quick Reference

```
User types message
  └─ message_type: "text", option_id: null
  └─ NLU runs, intent/category/sentiment extracted

User clicks option button
  └─ message_type: "option_select", option_id: <button id>
  └─ NLU skipped, flow transitions via option_id

User completes upload
  └─ message_type: "upload_complete", option_id: "upload_complete"
  └─ NLU skipped, flow transitions

Response render_type → action
  "options"  → show buttons, disable text input
  "upload"   → show upload card, validate files, send upload_complete
  "handover" → show handover card, disable everything, session over
  "text"     → show bubble, re-enable text (unless terminal=true)
  "text_input" → show text field, user types freely

Always:
  context  = response.next_context   (store for next turn)
  transcript.push({role:"bot", content: response.message})
```
